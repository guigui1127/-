# Session Handoff（交接筆記）

在你要 /clear 或結束一個任務段落之前，產出一份交接筆記，讓新開的對話可以直接接手，不用重講一次。

這份交接筆記是給「下一個你」看的，不是寫給別人看的報告。

## 什麼時候觸發

使用者說：「交接」「session handoff」「幫我做交接」「clear 前先總結」「收尾」，或任何類似的講法。如果使用者說要 /clear 但還沒做交接，也可以主動提醒一次。

## 語言

用繁體中文交接。標題與結構可以保留英文骨架方便辨識，但敘述內容用繁體中文。建議避免用破折號（「—」「——」），改用冒號、逗號、句號斷句。

## 怎麼產出交接筆記

回頭看整場對話，不是只看最後幾輪。只看最後幾輪會漏掉重要的東西。

依序檢查這些來源：

1. 這次對話提到的計畫檔（如果有指定路徑，先去確認內容）
2. 待辦清單，還在進行中或還沒做的事
3. 用背景模式開的程式或工作，這些的 ID 一定要留給下一個人，不然找不到
4. 這次對話新增或修改過的檔案，你自己知道改了什麼，不用重新搜尋
5. 這次對話裡寫過或更新過的記憶檔案（如果有設定記憶系統的話）
6. 還沒解決的問題：你問過使用者、但沒得到明確答案的事，或使用者提過、但一直沒處理的事
7. 整個專案是做什麼的：對話裡講過就照對話寫；沒講過的話，只看 repo 根目錄的 README、CLAUDE.md 和最近幾筆 commit 訊息，或這次碰過的檔案，用一兩句話帶過

不要去翻整個檔案系統重新確認。這是「這次對話發生了什麼」的整理，不是全面稽核。沒碰過的東西不用寫進來。

## 輸出格式，每次都照這個結構

```
# 交接筆記，<一句話：這次在做什麼>

## 專案目標
- 整個專案：<一兩句話：這個 repo 或專案整體在做什麼，讓沒看過它的人也懂>
- 這次對話：<兩三句話：使用者這次要的是什麼、過程中浮現的關鍵限制或框架>

## 這次定案 + 做完的事
- <決定或改動>，<為什麼，存在哪個檔案（完整路徑）>
- ...

## 目前進度
<一句話：現在做到哪裡，例如「X 已寫好並 commit <hash>，push 到 <分支>，還沒開 PR」>

## 下一個人要先看的檔案
- `<完整路徑>`，<為什麼下一個人要先看這個>
- 計畫檔：`<路徑>`（如果有計畫檔驅動這次對話）
- 這次碰過的記憶檔案：`<路徑>`（如果有）

## 現在還在跑的東西
- 背景程式：<ID + 是什麼 + 怎麼關掉>，或「無」
- 開發伺服器 / 連接埠：<網址 + port>，或「無」
- 開著的工作分支：<路徑>，或「無」

## 怎麼確認東西還是好的
- `<指令>`，<應該看到什麼結果>
- ...

## 先放著的事 + 還沒拍板的問題
- 先放著：<項目>，<為什麼先放著>
- 待拍板：<需要使用者決定的問題>，<背景>

## 下一步從這裡接
<一兩句話：新的對話最可能先做的事>
```

## 硬規則

- 只在對話裡輸出，不要寫成檔案，也不要更新記憶。
- 不要憑空編東西。哪個區塊沒東西可寫，就寫「無」，不要整段跳過。結構固定，這就是重點。
- 路徑一律寫完整路徑。下一個對話的工作目錄可能不一樣。
- 如果有計畫檔驅動這次對話，把它列在「下一個人要先看的檔案」的第一條。
- 「專案目標」兩行都要寫：「整個專案」講 repo 或專案本身的用途，「這次對話」講這次的任務，不能只寫其中一個。真的判斷不出專案用途，就寫「無法從這次對話判斷」。
- 「目前進度」只寫一句話，講清楚現在的狀態（做到哪一步、改動有沒有 commit 和 push、有沒有開 PR、卡在什麼），讓人不用讀完其他區塊就知道做到哪裡。它講的是「現在在哪」，「下一步從這裡接」講的是「接下來做什麼」，兩個不要混在一起。
- 不加表情符號、不加浮誇語氣、不寫「做得很好」這種總結。要簡潔具體：路徑、指令、程式 ID、決定。像一個資深工程師交班時會寫的東西。
- 有開背景程式的話，ID 一定要出現在「現在還在跑的東西」，附上關掉的指令，不然下一個人根本找不到。

## 不要做這些事

- 只看最後三輪對話就寫，這不是交接。
- 檔案路徑寫成相對路徑。
- 「現在還在跑的東西」因為沒有東西在跑就整段跳過，要寫「無」。
- 「專案目標」只寫這次對話的任務，漏掉整個專案在做什麼。
- 「目前進度」寫成好幾條，或把進度拆散到其他區塊，讓下一個人自己拼。
- 把交接筆記寫進檔案裡，這個技能設計上就是只在對話裡輸出。
- 加一段「這次做得好不好」的檢討。
- 除了「下一步從這裡接」那一句話以外，不要多給建議。下一個對話自己會判斷，你只負責交接。
